# Core patches

Every change we make to files that come from upstream FreeCAD is listed here, so upstream merges stay
predictable. New behavior should live in `src/Mod/Studio`; an entry here means no extension
point was available.

| 2026-11-15 | `src/Base/CrashReporter/Writer.h`, `src/Base/CrashReporter/Writer.cpp`, `src/App/Application.cpp`, `tests/src/Base/CrashReporter_tests.cpp` | Windows: the crash reporter's prewarm (`cpptrace::generate_object_trace`, which loads dbghelp) runs on a worker thread 5 s after startup (`Writer::prewarmInBackground(delay)`) instead of during it. A crash before it starts cancels it (`Writer::stopPrewarm`) and captures as it did before prewarm existed; a crash while it runs waits for it (at most 2 s), so dbghelp is used by one thread at a time. Other systems unchanged (their prewarm sets up what the signal handler reads). Three new tests | Startup budget (PLAN 2.10, approved by the user): prewarm was ~266 ms of startup on the slim Release build. Run on a thread right away it competed with startup (the other phases got slower; net −40 to −190 ms); delayed, startup went from 1.67–1.74 s to 1.41 s. Also tried, not kept: FreeCAD's OpenGL check moved after startup (the OpenGL setup then happened when the window showed: no change) | Contained in `Writer` plus one call in `Application::initCrashReporter`. If upstream reworks prewarm, re-measure startup with `tools/bench/profile_startup.py` before re-applying |
| 2026-11-11 | `src/Mod/Start/StartMigrator.py` | First-run migration writes `ConfigGet("StartWorkbench")` instead of hardcoded `"PartDesignWorkbench"` | Bug: on every brand-new profile the 2024 migration overrode the branded start workbench. Covered by `StudioTests.test_branding` + `tools/test/startup_smoke.py` | **Good candidate to send upstream.** If upstream removes the 2024 migrator, drop this patch |
| 2026-11-19 | `src/Gui/Navigation/NavigationStyle.cpp` | `openPopupMenu`: calls `initAction()` on `Std_ClarifySelection` before reading its action's text and shortcut | Bug: right-clicking an object in the 3D view crashed FreeCAD ("Illegal storage access", an access violation at address 0x10; the user's report). Covered by `StudioTests.gui.test_context_menu` (red: that crash on the first right-click; green with the fix) | **Good candidate to send upstream**: any workbench without the Tools menu crashes the same way. The same unchecked `cmd->getAction()->` is in `src/Gui/ViewProviderLink.cpp` (`Std_LinkSelectLinked`, in a link's menu), not changed: Studio keeps the View menu, whose Link actions group makes that action, so it can't fail today. Re-check if Studio ever drops the View menu |
